## 2. 三种操作的校验边界

| 操作 | 允许或要求 | 结果 |
| --- | --- | --- |
| 保存草稿 | 允许名称空白、无动作、空组、缺剂量／单位／休息／侧别，以及数字框中的未完成或错误文本 | 原样保存，显示“草稿 · 待完善”；不启用、不生成训练事实 |
| 导入计划文件 | 文件可读、严格 JSON、当前 v4 格式、完整处方、有效且一致的身份和来源引用、符合新建／升级规则 | 全部合格才导入为草稿；否则列出问题，零计划写入 |
| 预览并启用 | 草稿可转换为完整处方，符合所有领域规则及动作／内容可用条件，版本与目标未过期 | 展示完整处方、差异和提示；用户确认后事务性启用 |
| 开始训练 | 所选版本已启用；重新检查其当前可用性、预览时效与已有进行中训练约束 | 校验及确认通过才由会话控制器启动并冻结训练所需事实 |

“草稿允许保存”只放宽内容完整性，不放宽存储格式、身份完整性、写入权限、
并发令牌或数据根支持边界。存储失败必须明确报告，不得显示“已保存”。
未知数值仍是未知，不补 0、不使用建议值冒充用户输入；已有历史未知事实遵循原规则。
未审核内容继续按现行规范提示并记录，不新增“必须审核才能启用”的门槛。

## 3. 草稿交互与持久化

### 3.1 用户看到的行为

- “保存草稿”始终独立于“预览并启用”。保存可同时提示“已保存，有 N 处待完善”，
  待完善项不阻止落盘；保存之后重新打开恢复全部原文、顺序和未完成的成员／剂量行。
- 名称为空时，列表使用“未命名草稿”及保存时间区分，不将占位名称写成用户名称。
  全空新计划也可保存，不强迫先加一个动作。
- 添加动作或组尚未完成时也能保存：将其作为明确的未完成草稿节点保留，
  不能由“完成添加”先行校验而挡住整份草稿保存。放弃该节点仍是独立明确操作。
- 保留现有紧凑保存确认、固定底部按钮和可展开差异。尚无法形成正式计划编号时，
  明示“草稿编号”与“正式计划编号待确定”，不拼出虚假的正式版本。
- 点击“预览并启用”时，展示全部可独立确定的问题。点击问题跳转并聚焦相应
  动作／组／成员／剂量字段；修改后重新检查，不强制逐个弹框试错。
- 编辑已启用计划仍建立升级草稿。未完成升级不影响旧版本的启用状态或正在进行的训练。
  训练页只执行明确选中的已启用版本，不能以草稿冒充可训练计划。
- 关闭未保存编辑仍提示保存草稿、放弃修改或继续编辑；本期不增加定时自动保存。

### 3.2 推荐存储方案

新增独立的草稿编辑文档存储，不把不完整值直接写进现有规范化处方表。
原因是现有仓储按完整 day/item/set 重建处方，校验、差异、启用、训练及资料导出
均依赖这一结构；只删除保存时的校验会把错误传播到所有消费者。

草稿文档拥有稳定标识、内部格式版本、编辑令牌、创建／更新时间、用途（新建／
复制／升级／编辑已有草稿）、关联计划与源版本，以及完整编辑内容。数字输入保留
原始字符串，空白、尚未选定和“不适用”分开表达；节点标识和层级由领域模型维护。
不保存 Qt 控件、焦点对象或界面缓存，不把草稿内部格式加入外部计划合同。

具体写入和转换约定：

1. 新建或复制草稿先取得内部草稿标识；正式基础编号在首次成功形成完整处方时分配。
   用户明确填写的复制编号／名称先作为待校验输入保留，冲突时阻止转换或启用，
   不因此丢掉草稿。空名称不进入现有计划名称唯一约束。
2. 编辑现有草稿时以编辑文档作为其当前编辑内容，列表只显示一项，不能同时展示
   旧完整快照并误称为最新内容。打开时若尚无编辑文档，从已保存处方无损生成。
   活动版本不建立可覆盖自身的编辑文档，必须走升级草稿。
3. 每次保存首先提交编辑文档。只有完整处方校验通过，才在同一用户动作的事务内
   创建／更新规范化草稿；不完整时保留编辑文档，不让旧快照成为启用目标。
   文档保存、规范化更新、编号占用和关联更新要么全部成功，要么全部回滚。
4. 升级草稿绑定源活动版本。完整且确有差异时沿用结构变更／剂量文字变更的
   `AA`／`DD` 规则计算编号；尚未完成或与源相同时允许保存编辑文档，
   但不创建没有变化的正式升级版本。启用前重新确认源仍是最新活动版本。
5. 启用用例读取最新编辑令牌，将文档编译为处方并重新校验，随后按原事务边界
   固定内容、替代旧活动版本和更新指针。任何失败均保留草稿和旧活动版本。
6. 列表、预览、差异、复制、删除、根备份／恢复和引用影响分析均识别新草稿。
   资料导出不得把尚未完成的编辑文档伪装成合格 v4 计划或训练证据；本期不提供
   未完成草稿交换格式，点击导出时中文解释需先完善的内容。

内部草稿格式也需可识别版本并拒绝未来格式。数据库增表按 schema 修订处理，
实施时应用版本至少提升补丁号，同步身份与支持映射；不在规划阶段占用下一版本号。
现有活动版本、完成训练、导入原件和冻结证据不重写；仅从当时明确支持的数据根升级，
不访问旧项目数据库或自动发现个人数据根。

## 4. 文件导入与问题清单

这里的“上传”在原生客户端表现为选择本地文件，无需服务器或网络传输。
本期继续只支持 UTF-8 JSON、`training_feedback.plan` v4；不扩展 Excel、Word、
自然语言识别、旧格式转换或旧提交包兼容。入口明确显示支持格式和当前规则说明，
提供可保存的当前格式说明／示例；示例仅作格式参考，剂量不作为用户事实自动入库。

导入分为只读解析、校验预览、确认写入三个阶段：

1. 读取用户选择文件的字节快照，检查编码、JSON 语法、重复键、非有限数字和版本。
   无法解析时显示行列位置及修正说明；不能解析的文件不继续做伪造的字段检查。
2. 校验 schema、领域规则、动作精确版本、名称／分类一致性、来源引用和新建／升级
   目标。可检查的独立问题集中列出；父结构失效时不追加一串无意义的子字段错误。
   旧格式、未来格式及训练证据文件显示类型／版本不符，并指向当前格式说明。
3. 合格时展示计划摘要和变化，用户确认后针对同一份字节快照，在事务内复核状态，
   创建草稿并登记保留的原件。取消不创建计划；原文件始终不改写。
4. 不合格时不创建半份草稿、不暂存为“成功导入”；显示“导入失败，尚未保存计划”，
   提供可复制的中文问题清单，供用户修改原文件后重新选择。
5. 数据库提交与托管原件落盘沿用明确的失败清理机制；失败不留下成功记录，
   文件清理失败另行报告。不得把数据库事务误称为可以自动回滚文件系统。

文件合格与启用资格分别表达：完整合法但动作当前未启用或指导缺少有效图片的文件，
可按现有规则导入草稿，同时列出启用前须处理的事项；缺失或不匹配的动作／内容
身份属于文件无效，直接拒绝。导入不自动启用动作、审核内容或启用计划。

统一问题结构建议包含稳定问题码、字段路径、节点标识、严重程度和修正参数。
领域层返回事实，应用层汇总并决定能否继续，UI 只翻译、呈现和定位。例如：

- “第 3 个动作「深蹲」→ 第 2 组 → 数值：尚未填写，请填写有限的非负数。”
- “第 2 个动作组 → 第 1 个成员 → 先做哪一侧：尚未选择，请选择左侧或右侧。”
- “计划名称：已有同名计划，请修改名称；如需更新原计划，请按升级格式填写。”

导入问题附带可复制的文件字段路径以便修改，主说明仍为中文。
同一规则供手工草稿编译、导入、启用和训练启动复用，保留各阶段的严格程度，
不能在 UI 再写一套业务判断。现有首次报错改为有结构的汇总，仍保留异常兼容出口。

## 5. 中文范围与例外

中文要求覆盖导航、菜单、按钮、标签、占位提示、工具提示、状态、空态、表格、
预览／差异、训练／历史、设置、文件筛选说明、确认框、通知及错误说明；
程序拥有的 Qt 默认按钮、右键菜单和标准对话框文案也纳入处理，必要时使用中文
翻译资源或显式中文组件，不能依赖操作系统恰好为中文。安装与卸载自有提示继续中文化。
外部网站及系统自身界面不冒充客户端可控文案。

允许保留的内容限定为：

- 产品／品牌名和必要技术专名，例如 TrainingFeedback、Windows、GitHub、JSON、SQLite；
- 必须准确引用的动作专名或缩写；已有明确中文名称的普通功能不能以“术语”为由保留英文；
- 用户原文、引用原文、文件名／路径、网址、版本号、计划编号、字段路径、哈希及错误码。

这些例外不翻译或改写用户事实。内部枚举、SQL、JSON 键名、状态码保持机器合同，
显示时通过集中映射转成中文。未知枚举显示中文兜底并附必要标识，不能直接裸露英文。
未知异常主说明中文化；原始英文堆栈或第三方异常保留在诊断日志／可复制诊断材料中，
客户端正文和展开详情不直接倾倒整段英文。诊断入口自身也使用中文。

以 `src/training_feedback/ui/labels.py` 和 `src/training_feedback/error_messages.py`
为现有入口，静态审阅所有用户可见出口及目录自有说明，区分程序文案和原文。
不以“源码出现英文字母”为判错标准，也不做自动全文翻译或修改历史用户内容。
