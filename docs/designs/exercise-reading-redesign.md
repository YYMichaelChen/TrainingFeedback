## 1. 目标与范围

将动作详情改为以阅读为主的界面：**宽屏左图右文，图片默认完整显示，
指导分组展开，管理操作统一收进“更多操作”**。

用户反馈的现状是：示意图需要上下滚动，指导展示缺少层次，底部按钮过多。
当前实现虽然会缩放图片，但高度仍随宽度增长，没有受到可视区域高度的约束；
底部三排操作又压缩了阅读空间。

实施范围为动作库详情、外部审核表单中的阅读区域、冻结指导弹窗。
训练执行页的布局和记录操作、动作库卡片列表不调整。
不改写动作指导、不生成或替换示意图，不改变审核和启用的业务含义。

原方案落档授权仅保存方案及文档路由。后续用户已明确授权 v0.8.11 开发，
本次实施包括以下阅读范围与应用版本轮换；源码交付后用户追加授权打包及 GitHub 发布，
按实际候选记录身份与证据，不扩大验证范围。

## 2. 页面布局与图片体验

### 2.1 详情页结构

```text
← 返回动作库    臀桥                         更多操作 ▾
使用状态 · 审核状态 · 启用状态

┌────────────────────┬──────────────────────────┐
│                    │ 怎么做                 ▾ │
│   完整动作示意图    │ 起始姿势、步骤、呼吸节奏 │
│   等比缩放、居中    │                          │
│                    │ 安全提醒               ▾ │
│                    │ 停止条件、注意事项等     │
│                    │                          │
│ 图片说明           │ 认识动作               ▸ │
│ ‹    1 / 3    ›     │ 进阶与退阶             ▸ │
└────────────────────┴──────────────────────────┘
```

- 删除现有三个顶层标签和底部三排按钮。顶部仅保留返回、动作名称、更多操作，
  状态信息另占紧凑一行。
- 图文主体使用剩余高度，不让图片原始尺寸撑高页面。左右初始比例为
  45%／55%，支持拖动分隔线。
- 主体可用宽度达到 **760 个 Qt 逻辑像素**时并排显示，
  图片栏最小宽度 300，文字栏最小宽度 400。
- 小于该宽度时，切换为“动作指导／示意图”两个阅读标签，默认显示指导。
  窗口变窄时不改成上下堆叠长页；恢复宽屏时保留当前阅读位置。
- 延续现有深蓝、青绿与浅灰配色。采用白色阅读面板、轻边框和明确留白；
  新增样式限定到阅读组件，不改全局按钮尺寸或侧栏。

### 2.2 示意图默认展示

- 按图片区的实际宽度和高度共同计算缩放比例，等比居中、完整显示，
  不裁切、不拉伸。
- 图片说明和翻页控件占用的高度先扣除，再计算图片区域；
  默认图片区没有横向或纵向滚动条。
- 多张图按原声明顺序逐张展示，只有多图时显示前后切换和页码，
  不再纵向叠放所有图片。
- 缺失或损坏图片保留其位置、说明及明确原因，不跳过后伪装成全部正常；
  指导文字仍可阅读。
- 长图片说明显示两行预览，可点击查看完整原文，不无限挤占图片高度。
- 全程使用原图数据生成显示结果，不重写图片文件，不改变内容身份、哈希或审核资格。

### 2.3 放大查看器

- 点击图片打开可调整大小、可最大化的查看器，初始适应窗口完整显示。
- 工具栏提供“适应窗口”“实际大小”和缩放比例；支持滚轮缩放、
  放大后拖动查看、Esc 关闭。
- “实际大小”按源图的逻辑尺寸显示；缩放范围为其 10%～400%，
  适应窗口允许低于下限。
- 适应模式随窗口大小重新计算；手动缩放后保持当前倍率，
  点击“适应窗口”恢复。
- 原图始终是缩放来源，避免对已缩小的图反复放大造成模糊。
  Qt 高 DPI 换屏时重新渲染。
- 默认无需滚动看全图；小字可通过主动放大查看，
  不承诺所有尺寸的长图在缩小后仍能直接读清。

## 3. 指导内容与管理操作

### 3.1 指导阅读

指导区只有一个纵向滚动容器，分组内不再出现独立滚动框。

| 分组 | 字段 | 默认状态 |
| --- | --- | --- |
| 怎么做 | 起始姿势、动作步骤、呼吸、节奏或保持 | 展开 |
| 安全提醒 | 停止条件、注意事项、常见代偿 | 展开 |
| 认识动作 | 训练目的、主要及次要身体部位、应有感受、适用情况、所需器械 | 折叠 |
| 进阶与退阶 | 退阶方式、进阶方式 | 折叠 |

- 步骤采用独立编号和悬挂缩进，长文本自然换行；呼吸、节奏各有清晰的小标题。
- 安全提醒使用浅色强调背景与文字标签，不只依赖颜色，
  也不把普通提示全部渲染为危险警告。
- 保留字段原文、换行、步骤顺序和已有编号，不生成摘要、不改写指导，
  不从图中推导新指导。
- 空字段明确显示“未填写”；图片及说明仅在图片区展示，避免指导中重复嵌图。
- 用户可临时折叠任何分组；切换到另一动作或内容版本时恢复默认展开状态。
  窗口变化不重置折叠状态。

### 3.2 更多操作菜单

“更多操作”使用一个按分隔线分组的菜单：

| 分组 | 入口 |
| --- | --- |
| 使用管理 | 使用当前内容；启用动作或停用动作 |
| 内容维护 | 编辑动作内容…；复制为自定义…；替换为本地示意图… |
| 审核 | 审核事件…；记录外部审核…；撤销当前审核 |
| 生命周期 | 移除与恢复审核… |
| 信息 | 内容信息… |

- 启用和停用只显示与当前状态对应的一项；使用中、未审核、
  有更新内容等状态继续明确区分。
- “内容信息”只读展示来源、动作族／变体、当前与已选内容身份、
  目录版本和图片资格，避免把技术信息铺在阅读正文。
- 各写操作继续调用现有应用服务，保留现有确认、事务和错误提示。
  不合并“使用当前内容”“启用”“审核”，不在阅读时自动改变状态。
- 菜单打开及执行时绑定当前显示的准确内容目标；内容变化后重新读取状态，
  不能把操作落到旧动作上。

### 3.3 审核事件弹窗

- 详情页不再保留审核事件标签；通过“更多操作 → 审核事件…”打开只读弹窗。
- 标题明确动作名称及当前内容版本，按时间倒序展示记录／撤销事件。
- 每条事件展示记录时间、实际审核时间、来源、原始备注、
  已保存答复原件信息；未知时间和未附原件明确标注。
- 没有记录时显示“当前内容版本暂无审核事件”。
  不把其他版本的审核混入当前有效审核。
- 弹窗只负责查看，记录及撤销仍使用菜单中的独立操作。

## 4. 实现边界与实施顺序

1. **先建设独立阅读组件。** 在 UI 层新增分组指导视图、
   适应可视区域的图片面板及放大查看器。保留旧阅读组件供训练执行页继续使用，
   避免共享组件替换导致范围外变化。
2. **替换动作库详情。** 接入响应式图文布局、顶部菜单、内容信息及审核事件弹窗，
   移除旧标签和底部按钮区。
3. **统一弹窗阅读区域。** 外部审核表单继续保留目标选择、审核信息和确认控件，
   只替换图文阅读部分；冻结指导弹窗保留动作选择与关闭入口。
4. **保持数据来源分离。** 动作库和审核读取现有服务提供的精确内容与已校验图片；
   冻结指导读取会话快照及冻结图片，绝不回退到最新目录内容。
5. **整理文档与执行记录。** 后续进入实施时，将本文关联到实际发布设计；
   确需改变的持久产品规则归入产品规范。Planscope 只记录任务、阶段和下一步，
   变更后运行 `plan.py sync`。原方案落档未创建活动发布；本次实施使用 v0.8.11。

接口只新增 UI 层阅读组件及其内容更新入口；不增加数据库访问、业务规则或外部协议。
图片加载仍通过既有服务，组件不自行解析用户数据目录。

现有实现入口：

- [动作库详情及审核表单](../../src/training_feedback/ui/catalog_library_page.py)
- [指导字段与旧阅读组件](../../src/training_feedback/ui/guidance_widgets.py)
- [现有图片组件](../../src/training_feedback/ui/illustrations.py)
- [训练执行页及冻结指导弹窗](../../src/training_feedback/ui/group_training_page.py)

本方案不需要数据库迁移、目录内容更新或协议变化。v0.8.11 实施轮换应用版本，
源码交付时没有打包或发布；后续追加分发授权另行记录，不改变个人数据状态。

## 5. 验证与完成标准

以下作为实现时的代码审阅标准，不转化为额外功能测试或用户手测清单：

- 横图、竖图、方图均使用双向边界适配；长图、多图、长说明不撑高详情页。
- 窄窗口和高 DPI 布局可收缩；指导原文可访问、可选择复制，安全字段默认展开。
- 图片异常不阻断文字阅读；冻结内容不被当前目录内容替换。
- 菜单操作保留原有目标、确认及事务语义；审核事件不被误呈现为新版本的审核证明。

遵循[产品规范 §9.1](../development-plan.md#91-release-and-follow-up-boundaries)
与[测试说明](../../tests/README.md)：原方案纯文档落档应用测试 **0 项**、
人工测试 **0 项**。仅做文档静态检查，不操作客户端，不读取真实用户数据。

实施开发默认仍为 0 项；仅在具体改动造成启动失败风险时，
说明因果关系并选择通常 1 项、最多 3 项已有隔离检查。
静态检查限于改动文件和相关文档，不开展 GUI 自动化、功能回归或批量人工验收。
未运行不记为通过，按政策取消的检查不形成待补任务。

原方案基于用户提供的截图和只读源码检查；后续候选构建的身份与限制由开发记录承接，
不声明重设计后的界面效果、客户端行为、公共验收、外部内容审核或 W4 已通过。
