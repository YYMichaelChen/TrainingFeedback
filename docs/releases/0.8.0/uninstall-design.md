# v0.8.0 卸载助手接口与故障模型

状态：T-004 设计完成，T-006 已实现代码路径；客户端验收尚未运行。
实施和验证见 [实施记录](implementation.md)。范围由 [发布设计 §2](design.md#2-可选用户数据卸载)
及 [产品规则](../../development-plan.md) 决定；本文件细化实施，不代表候选验收。

## 所有权与入口

只读取当前 Windows 用户的固定 locator，最多检查它指向的一个确切根。
不接受安装器传来的任意数据根字符串作为删除授权，不查找历史根。
安装器负责默认未选中的删除选项、路径/内容展示和二次确认；应用层协调
预检与提交，数据层负责只读校验、Windows 文件身份、锁、清单和恢复记录。
独立助手不创建 QApplication、窗口或 LibraryContext，也不运行迁移/重置。

两次自定义窗口尺寸手动检查失败后，卸载选择改用Inno维护的TaskDialog。
第一个选项始终是仅卸载并保留数据，删除为独立的明确选择，不再使用复选框。
归属等预检失败时只提供仅卸载和取消，不提供删除入口。选择删除后仍展示确切
路径并二次确认，默认“否”；拒绝二次确认直接取消本次卸载。Esc、关闭窗口、
取消和对话框失败不删除；静默/KEEPDATA仍保留。变化只涉及控件与取消反馈，
默认保留、明确选择和再次确认的产品边界不变。

助手以同一程序 payload 中独立的内部 CLI 入口运行，在 Qt 主程序导入前分派，
避免重复打包 Python/Qt。安装器在删除程序 payload 之前调用。
助手完成或明确报告失败后才允许普通程序卸载；无法启动助手时数据删除禁用。
失败/部分删除时，用户可取消程序卸载以保留助手重试；若继续只卸载程序，
保留 locator 和恢复记录，重装同一当前版本助手后可重试。
助手不能因 Qt 主程序退出码为零而宣称删除完成。

## 可测试的应用接口

| 操作 | 输入 | 输出 / 副作用 |
| --- | --- | --- |
| `probe` | 可信程序目录、当前用户身份、固定 locator 位置 | 只读 `CleanupOffer` 或禁用原因；不修复数据根，不创建根内锁文件 |
| `prepare` | 明确选择删除；再次读取 locator | 独占会话、规范化完整路径、删除清单、短期 token；向调用方展示后等候确认，不删除数据 |
| `cancel` | 会话 token | 释放文件句柄/锁，移除本次未提交的临时会话；不改 locator、数据库或用户文件 |
| `commit` | 同会话 token、二次确认 | 再校验身份和清单；写持久恢复记录后执行；返回完成或实际剩余项 |
| `retry` | 当前用户固定位置的既有恢复记录；再次展示并确认 | 只清理已绑定的同一目录身份；不得以新输入路径替代原目标 |

token 只是确认绑定，不是权限凭证。所有写入前重新验证当前用户、路径身份、
locator 原始字节和删除目标；任何缺失/未知 token、未确认、过期会话直接拒绝。
CLI 只提供这些受控命令与结果文件/通道，不暴露 `delete <path>`。
安装器通过参数数组或明确引号规则调用，用户路径不得拼成 shell 命令。
正式接 Inno 前，T-006 用最小进程原型锁定会话生命周期和 IPC 编码；若无法
跨确认阶段持有句柄，则必须在 commit 重开全部受保护句柄并重新核验清单。

`CleanupOffer` 至少包含：规范化路径、数据库/根内文件分类、文件数/字节、
所有拒绝原因，以及仅用于内部比较的卷/目录身份、locator 摘要和清单摘要。
界面展示全部根内内容均会删除，包括未知文件；根外导出/备份不在清单中。
未知文件不能被隐式排除后仍宣称整根删除，也不能扩展为根外删除。

`CleanupResult` 使用可区分状态：`retained`、`cancelled`、`refused`、
`root_removed_locator_retained`、`partial`、`complete`。携带实际保留路径和
重试提示；机器可读错误码与用户说明分开，普通诊断不记录个人内容。
结果与内部恢复记录版本独立于 plan/evidence wire contract，尚未发布。

## 路径和只读预检

顺序固定：先验证字符串/路径边界，再打开确切目录句柄，最后只读验证元数据
和 SQLite。不能先 `resolve()` 穿过重解析点，再把解析后的路径视为授权目标。
大小写、尾随分隔符和点段在安全比较中规范化；界面显示最终完整路径。

以下情况禁用数据删除，但允许仅卸载程序：

- locator 缺失、畸形、不是普通本用户文件，或指向非绝对本地目录。
- UNC、设备命名空间、盘符根、用户主目录/其祖先、Windows/Program Files
  保护范围、程序目录或 locator 所在目录，以及与这些范围重叠的根。
- 路径任何一级或根内任何项有重解析属性；不只检查 symlink/junction。
  Windows 的重解析点还用于挂载目录等机制，见
  [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points)。
- 根/locator 所有者不属于当前用户，或所需读取/列举/删除权限无法确认。
  不提权、不取得所有权、不改变 ACL；未支持的文件系统直接拒绝。
- marker/config 的应用、format/model 不匹配，schema 非当前、数据库完整性
  或外键检查失败，发现未完成升级/重置/其它清理状态。
- 根正在使用；无法取得独占 RootLease 或数据库存在冲突打开句柄。
  不能杀死未知进程。提示关闭应用后重新探测。

复用的语义：`inspect_existing` 的只读元数据/schema/integrity 校验、
`require_library_root` 的 model 校验、`RootLease` 的应用连接互斥。
不能调用 `open_existing`：它会执行 `prepare_existing_root` 并打开可写 Database。
不能直接复用 `managed_path` 做删除授权：它服务于资源读取并会解析链接。
现有 RootLease 会创建锁文件，因此 probe 必须只读，prepare 对已通过校验的
根取得既有锁；若锁文件不存在，应使用不改根的安全锁方案或禁用删除。

## 身份、清单与执行边界

在 Windows 后端中打开根、关键父目录与每个拟删除项的句柄，拒绝所有
重解析属性，并绑定卷身份、file ID、类型和父子关系。持有防止目录被替换的
句柄直到删除/确认结束；仅比较路径字符串、mtime 或 metadata hash 不足以防替换。
[GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex)
提供句柄信息类；
[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)
支持通过句柄改变文件信息。具体分享标志、删除标志、目录枚举与句柄数量限制
必须在 T-006 的 Windows 合成目录原型中证明，不能以这些 API 的存在当作安全测试通过。

清单只能由已绑定根枚举得到，使用相对组件，不存通配符；不沿链接遍历。
确认后的新增项、替换项、locator 变化或无法取得句柄均停止并重新预检。
删除按清单自底向上，Windows 后端在句柄绑定的对象上操作；禁止对 locator
字符串调用通用 `shutil.rmtree`、Inno `DelTree` 或 `UninstallDelete`。
与根外相连的硬链接需明确处理：保守拒绝多链接文件，避免实现错误改写共享内容。

不重命名数据根或移到一个新猜测路径。文件删除不可事务回滚，必须用持久
记录区分“尚未开始”和“已经部分完成”。仅当全部目标消失、原根身份确已
移除后，才对预检绑定的同一 locator 做条件删除。locator 被另一会话改写时
保留它，返回 `root_removed_locator_retained`，不得删除新的指针。

## 中断与恢复

在固定本用户应用位置保存最小恢复记录，不能置于将被删除的根中。
记录含本用户身份、原始确切路径、卷/根身份、locator 摘要、确认清单、
已完成/剩余项、阶段与内部版本。使用原子写入，拒绝链接/未知格式；保存
失败时尚未删除任何用户数据。记录只服务恢复，不作为普通日志上传/持久诊断。

状态顺序：`prepared` → `deleting` → `root_removed` → `locator_removed` → `complete`。
每项删除前持久化操作意图，删除后记录结果；崩溃重试允许同一项已不存在，
但路径存在时必须与记录的身份一致。缺失/无效记录、身份不一致或出现新文件
不能继续；保留剩余物并报告。原根 marker/config/schema 即使已删除，也不能
通过放宽校验去猜测另一个根；只有可信记录绑定的剩余对象可继续处理。
完成后清除恢复记录；失败时报告根/locator/记录的实际保留位置。

恢复记录能够携带已知事实，不自动授权删除；每次 retry 再次要求明确确认。
所有者、记录完整性、相同身份验证、每步中断幂等性是 T-006 的必测风险。

## 验证清单

代码级测试使用独立合成 locator 和目录；T-005/T-006 各自选择受影响用例，
最终候选按同一个 minor release scope 重新选择必要风险。

| 风险 | 必需验证 |
| --- | --- |
| 未选中/取消 | 不调用清理写入；根/locator/外部备份字节不变 |
| 路径边界 | 中文空格、大小写、尾分隔符；危险祖先/后代、UNC/设备路径拒绝 |
| 身份与重解析 | 实际 Windows junction/symlink/其它 reparse；确认后替换根/子目录，根外哨兵不变 |
| 元数据/schema | 当前有效根；畸形/未知/未来/不完整状态先验拒绝且无写入 |
| 使用中/权限 | 第二个当前连接、非应用数据库持有者、拒绝 ACL；不修改权限 |
| 部分删除 | 每个阶段注入失败/进程中断；准确剩余项，同身份可重试，替换对象拒绝 |
| locator 竞态 | 删除根后指针被改写时保留新指针；删除 locator 失败可重试 |
| 安装器/打包 | 独立助手完整 payload；Inno 显示实际路径、二次确认和真实错误结果 |

开发者手动客户端与安装器检查全部 `not run`。静态检查、合成目录代码测试
和进程原型不替代手动安装/卸载验收，也不建立旧版本兼容承诺。
