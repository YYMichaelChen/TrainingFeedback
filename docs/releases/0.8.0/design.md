无此风险为 0 项；人工测试默认 0 项。安装／卸载矩阵、性能采样、完整模拟训练及

## 目标与发布边界

v0.7.8 已先独立交付文档与知识治理修复。此后 v0.8.0 开发交付以下五项：卸载时可选择删除用户数据、安装时可选择程序目录、正式版前关闭旧版本兼容测试及支持承诺、清理项目冗余、以测量结果驱动应用级响应优化。剩余工作按下列顺序实现，不再预设其它 0.7.x 中间版；若后续确需独立可用的中间版，再按版本变更流程单独决定。方案本身不改变 schema/catalog/外部契约版本。

“正式版”由用户明确宣布。版本号到 0.8.0、制作本地安装包或完成本地验收，均不会自动宣布正式版或启动旧版本兼容义务。首个正式版建立基线；后续正式版在确有前序正式版本时，明确选定支持 **1 或 2 个旧正式版本**，选定范围写入当时的版本支持表；验证范围届时明确，不自动增加当前测试。正式版前不运行旧版本升级/回归/安装兼容检查，也不承诺旧版数据根能在新版打开。当前已有兼容代码在审计删除前可能仍可工作，但不构成承诺。所有阶段均须对未知/不支持数据根先校验再写入，拒绝时原目录不变；不扫描旧项目数据库。

## 1. 安装目录选择

现状：Inno Setup 脚本已有默认目录 `%LocalAppData%\Programs\TrainingFeedback` 和固定 `AppId`，未显式固定目录页显示方式。Inno 文档说明目录页受 `DisableDirPage` 控制，同一应用的旧安装目录可由 `UsePreviousAppDir` 作为默认值（[页面条件](https://jrsoftware.org/ishelp/topic_wizardpages.htm)、[旧目录规则](https://jrsoftware.org/ishelp/topic_setup_usepreviousappdir.htm)）。

实施：

1. 将目标目录页明确设为交互安装始终可见，保留上述默认目录及每用户安装权限；只预填经过程序归属、payload 和卸载器校验的现有安装目录，不直接继承 Inno 的历史目录。已经不存在的旧程序路径不是有效安装，不触发搬迁。安装界面显示最终程序路径，允许浏览或输入其它目录。静默安装沿用 Inno 的 `/DIR` 机制和其现有语义，不增加数据根参数。
2. 安装前校验目标：不得是盘符根、Windows/Program Files 系统目录、选中/已知数据根或其父子路径，也不得复用有无关文件的目录。对路径规范化、大小写、尾随分隔符、UNC、重解析点和权限失败做明确处理；应用二进制始终与数据根分离。目录实际路径再次在写文件前校验。
3. 同一 `AppId` 的原位升级沿用旧目录。若用户主动改到另一目录，先明确旧目录与快捷方式的处理方案，保证只有一个有效启动入口；不得把旧目录内未知文件当作安装器所有物删除。取消安装不改 locator/root；失败安装可恢复或明确报告不完整状态。
4. 构建清单记录实际 `{app}` 位置无关的相对 payload 与 hash；自定义路径下快捷方式、卸载入口、重装与卸载必须指向当前安装。验证只按第 9.1 节选取启动风险，不追加功能矩阵。

安装行为要求（保留实现语义，原逐项人工验收已取消）：

- 首次安装可选包含空格和中文的非默认目录，启动及快捷方式均从所选目录运行。
- 默认路径和原位升级正确；升级更改路径后无陈旧快捷方式/重复有效安装。
- 取消、不可写/非法/与数据根重叠路径被安全处理，locator 与合成数据根逐字节不变。
- 安装、卸载及重装不因程序路径变化而隐式重置数据根。

## 2. 可选用户数据卸载

助手接口、只读预检、Windows 目录身份和中断恢复的实施设计见
[卸载助手设计](uninstall-design.md)；代码实现见 [实施记录](implementation.md)，
实际候选操作结果见 [版本历史](../../history/README.md)；未运行的批量验收要求已取消。

现状：Inno 已提供普通程序卸载器；locator 仅记最后选中的一个数据根，不保存所有历史数据根。默认卸载只移除程序文件。卸载脚本可使用 [卸载事件](https://jrsoftware.org/ishelp/topic_scriptevents.htm) 展示选择与执行清理；Inno 对递归通配删除有明确风险提示（[UninstallDelete](https://jrsoftware.org/ishelp/topic_uninstalldeletesection.htm)）。

范围决策：只对当前 locator 指向且经验证为 TrainingFeedback 的**一个**数据根提供删除选项，并同时可删除该 locator；其它曾选过的根、外部备份、导出到根外的文件均不发现也不删除。当前 locator 不记录全部历史根，因此扩大到“全部历史数据根”须另行设计可信登记机制和生命周期；不得靠扫描磁盘推断。

实施：

1. 卸载界面默认不选择删除数据，首个选项为“仅卸载程序，保留数据”，只删除安装器拥有的程序文件/快捷方式，保留 locator、根与备份；取消卸载亦不碰数据。自定义窗口两次尺寸验收失败后改用Inno维护的系统确认对话框和独立删除按钮，保留原默认保留语义。
2. 删除选项同时显示完整规范化路径、预计删除内容（数据库、图片、备份、导出等根内文件）和不可恢复提示；明确选择后再次要求确认，默认“否”，拒绝直接取消卸载。无有效 locator、marker/config/schema 校验失败、根正在使用、路径与程序目录或用户主目录等危险范围重叠、路径含重解析点/连接、权限无法确认时不提供删除入口并显示原因；仍可仅卸载程序。
3. 删除实现由独立且可测试的应用/数据层辅助逻辑拥有路径验证和删除清单；Inno 只传递明确选项并调用受控逻辑。不得用宽泛通配符或 `UninstallDelete` 对 locator 中的字符串直接递归删除。执行前重新核验同一目录身份，防止选择后路径替换；只允许本用户数据根。先安全处理应用关闭/数据库连接，再执行删除。失败时报告实际保留路径与清理状态，不谎称“全部已删除”；设计可重试的中断记录，不把部分删除伪装成完整根。
4. 需要重新安装/恢复备份时，通过现有“打开已有数据根”流程；安装器不创建或迁移根。外部备份不在卸载器删除范围内。清理 locator 仅在数据根删除完成且确认属于本应用之后进行，以免删除失败时失去指向剩余数据的线索。

卸载行为要求（原逐项人工验收已取消）：

- 默认卸载/取消卸载后合成根、locator 和外部备份逐字节不变；程序文件及当前快捷方式按预期移除。
- 明确选择删除并二次确认后只删除界面列出的确切合成根及 locator；拒绝确认后取消卸载且不删除数据。
- 无效 marker、根外路径、程序目录、用户主目录、符号链接/目录连接、打开中的根及权限失败均不会越界删除；记录保留的路径与可重试状态。
- 重装后能直接打开仍保留的根；卸载行为不被当作旧版本兼容测试。

## 3. 正式版前后的兼容边界

前正式版：关闭“旧应用版本升级”作为发布门槛的代码测试、合成旧版根测试、旧安装包安装测试和手动客户端检查。当前版本的新建根、同版本重启/重装、读写事务、未知/未来格式的只读拒绝及失败回滚仍是实现要求；自动检查仅按第 9.1 节的具体启动风险选择，不因此增加安全回归矩阵。若主动变更 schema/外部 wire schema，仍同改至少提升应用补丁版本，写明新根格式；不为了旧根保留迁移通道。旧根不因不受支持而被改写或删除。

正式版宣布时：用户确定首个正式版基线，固定其应用/schema/契约映射及真实二进制。后续正式版在存在前序正式版本时选择支持其中 1 或 2 个，建立合成根与到期策略，保留选定升级路径；未来验证范围届时由用户明确决定，不自动运行代码级及独立安装兼容矩阵；过期/未来根先验只读拒绝。历史开发候选版不会自动变成受支持正式版本。若正式版声明与本地候选不同，必须对正式候选重新取得证据。

文档执行：同步修改开发计划、开发流程、测试说明、安装验收手册、版本索引和 AGENTS.md。历史 0.7.x 证据按当时规则保留事实，不倒填新政策、不把过去的 `not run` 改为 `pass`。正式版前的版本索引可标识“当前已实现读取路径”，但不得写成支持承诺。不同版本的历史文档清理需先提取仍生效的规则，保留 Git 可追溯性。

## 4. 项目瘦身

首次仓库/依赖审计和服务层测量见 [开发基线](baseline.md)，原始样本在
[baseline.json](baseline.json)。后续已执行结果见 [审计和复测](slimming-and-performance.md)；补齐客户端基线的要求已取消。

引用审计、文件体积和已有测量保留为瘦身证据；后续清理先核对引用与归属，不新增页面响应采样。记录保留／迁移／删除理由，不以文件数下降替代质量判断。

1. **文档**：保留一份现行产品规则、一份流程、一份当前支持表及候选证据；将重复的历史说明压缩为索引/版本事实。已过期完整记录按仓库流程归档/移除，避免保留无上限本地副本。旧版证据不能冒充当前规则，必要的行为规则先升入当前开发计划。
2. **代码与资源**：用静态引用、入口清单和已有打包 manifest 识别无调用模块、重复 helper、过期资源及旧 fixture。仅在证据证明无当前入口后删除。特别审计旧 schema migration、一次性 reset、历史 import/导出通道；保留当前新根初始化和只读拒绝必需部分。禁止清理用户根、原始导出或 Git 历史。
3. **测试**：删除仅验证已退役旧版本承诺且无现行安全价值的用例；保留既有测试库，本次不删除测试。留存用例不代表要求执行；每次更新仅按第 9.1 节选择启动风险，不通过拆分 scope 规避上限。
4. **打包**：核对 PyInstaller/Inno payload 的运行必需性，删掉源码内已无引用或打包中重复的大文件。如清理影响已约定的安装包，核对相关 manifest 和启动必需资源；不自动构建或增加功能回归。

每个删除批次独立可回退；交付清单列出被删文件、引用检查、影响版本/契约及前后体积。若某项用途不明，保留并记录，不以猜测清理。

## 5. 应用程序级响应优化

已执行的热点定位与测量结果继续保留。旧 p95 改善 30%、200 ms 无反馈停顿、
客户端 p50/p95 对比、160 次计时和预热均退出交付门槛。冷检查未达旧指标是已知
性能事实，不是待补验收或收尾阻塞。后续根据用户实际卡顿反馈定位和修复，
不安排录屏、统计表或重复采样，也不以取消测量宣称性能已经达标。

优先路径：

1. 复用已有诊断和具体操作反馈定位热点；不记录用户文本、路径或个人内容，不默认增加计时采样任务。
2. 减少启动/切根时重复读取与对象重建；优化 SQLite 查询与索引需先看查询计划，不能改变用户事实、排序或时间边界。
3. 对目录渲染、搜索和图片解码做增量/分页/缓存；缓存按根、catalog、内容版本及修改事件失效，避免跨根混用或陈旧显示。
4. 把纯读取、图片处理及可取消的长任务移离 Qt 主线程；数据库连接只在拥有线程使用。Qt 主线程更新控件；写操作仍由应用层协调并保持一次用户动作的事务语义，取消不留下半写入。
5. 错误／长任务给出可见状态与取消反馈；仅有具体启动失败风险时按第 9.1 节选择检查。页面切换、保存和流畅度问题等待实际使用反馈，禁止 GUI 自动化。

交付已有代码改动、实际测量结果和已知问题；不再要求新的对比表、性能阈值或客户端手测。证据不支持“明显变快”时不作该声明，也不因缺少该声明追加测量。

4. **响应优化**：保留热点修复及测量事实；非启动问题随实际使用反馈改进。
5. **v0.8.0 收尾**：核对五项实现、身份和实际结果；未执行但已取消要求的检查
   不再阻塞。后续更新最多 3 项启动风险检查，人工默认 0 项，不运行 minor
