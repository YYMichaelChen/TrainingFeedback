# 外部指导与计划审核操作手册 — 当前开发版

更新：2026-09-26。适用于 0.7.2 当前模型、plan/evidence v2。
规则见[开发计划](development-plan.md)第 4.6、5.1、9、12–13 节，
内容见[动作与计划规范](initial-exercises-and-plan.md)。
旧版 v1、手动接收内置草稿和 export-all 流程保留在 Git 历史，
不是当前操作入口。

当前仍为开发期。新增/修订动作、指导及配套图片必须落实到内置源内容和 catalog；
本地开发根中的覆盖不是交付。由用户明确决定何时转入个人数据；合成审核、训练和
演练记录不会因此变成个人事实。本手册不宣告内容审核、W4 或独立验收完成。

用户于2026-09-23确认：外部内容复核和W4为独立后续事项，不阻塞本地打包发布；

## 1. 开发内容与材料准备

1. 当前源catalog070-illustrated-3已交付36条指导和36张技术有效插图，均未独立外部复核。
   按稳定键核对名称/别名、族/体位、内容与图片身份；未来真实审核优先初始计划13项，
   再覆盖其余条目。用户已选择直接关联现有36图，不新增逐图内容验收作为本地发布门槛。
2. 修订以新的内容版本进入源内容，保留旧身份/快照；按最新格式和图片门槛构建 catalog。
   先确认所有有价值的开发修订已进入内置源，再淘汰旧开发根。不得自动发布个人素材。
3. 在明确隔离的开发根，用当前计划/会话页面生成 v2 证据；没有实际训练时使用计划范围
   `scope: plan_revision`，不得把计划剂量当成完成量。训练范围为 `scope: training_session`。
4. 记录应用/源码、catalog/schema、内容与图片哈希，保留同一次导出的 JSON/Markdown、
   `plan-response.schema.json` 和 portable `assets/`。审核者必须能看到实际图像字节。
   使用精确版本的指导材料；不要使用带合成审批的打包 fixture 作为真实审核内容。

| 材料 | 用途 |
| --- | --- |
| 原始 JSON / Markdown、图片资产 | 完整处方/指导/事实，保持原文；缺失历史资源明确标注。 |
| 内容/图片 manifest | 稳定键、版本、哈希、技术校验及材料身份。 |
| 审核请求与逐项清单 | 说明开发材料性质、13 项优先级与全部 36 项覆盖。 |
| 同次导出的回复 schema | 唯一当前返回格式；占位样例不是真实计划或意见。 |
| 外部答复原件 | 实际来源、发生时间、问题/依据，逐项对应版本。 |

开发内容审阅可以先进行；个人化计划判断所缺的能力、病史和反馈必须列为未知，
不能由指导里的预期感受/常见代偿反推用户经历。

## 2. 图片检查与真实审核

- 技术检查验证受管相对路径、包含范围、存在性、解码、非零尺寸和 SHA-256。
  缺图、占位、损坏或哈希不符的版本可读可编辑，但不能选用/启用/激活或新开训练。
- 审核者核对实际定义：目的、部位、起始姿势、支撑点、活动侧、步骤、方向、呼吸、
  节奏、计次、停止标准、进退阶、器械、适用性与图文一致性。技术通过不等于审核通过。
- 结论分为可进入用户复核、需修订复审或信息不足；保存原始答复和确实发生的来源/时间。
  发生时间初始为空，允许日期或带时区时间并保留精度；快捷填入需要用户明确操作。
  确认时间由程序另记，不能替代未知的审核发生时间。
- 当前审核针对精确内容/图片哈希。更改正文或图片生成未审核版本；切换目标清除
  未提交输入与确认，批量逐项选择并原子提交。答复原件受管保存。
- 图片失效使当前有效审核/可用性失效，但保留原事件与历史快照。撤销追加事件，
  不删除历史证据；修复同哈希资源不是新审核，不同字节不得继承旧审核。
- 审核、选择使用版本、启用动作和激活计划分别记录。完整正文＋有效图片但无审核的
  版本可按显式流程使用，预览必须披露；这不等于完成内容审核覆盖。

## 3. 动作组计划和 v2 回传

1. 从目标根导出当前证据及回复 schema；来源 ID 只在该根有效。不存在来源会话时保持 null，
   不把隔离材料里的 ID 粘贴成个人来源。新文件只接受 `training_feedback.plan` v2。
2. 外部答复给出完整计划、原始 rationale、稳定动作引用/内容版本、训练日、动作/组合、
   组内顺序、每轮剂量/单位、轮数、首侧/换侧、各层休息和转换说明。
3. “直腿后踢→消防栓”是四点支撑示例；俯卧抬腿接消防栓需明确体位转换。相同动作族
   不自动意味着同体位、相同难度或能够无缝衔接。例子不能成为默认训练剂量。
4. 导入仅保存草稿与原件。用户阅读完整展开顺序、差异、来源依据及未审核名单后，
   单独确认启用。预览变化须重查；取消/无效输入不保存，也不丢失正在编辑的文字。
5. 激活绑定指导/图片；内置内容更新不会重写活动处方。调整内容、成员或被下架动作需新草稿。
   证据区分逐位置实际结果与组汇总，不能把汇总再计一次或把未知侧补成已完成。

开发阶段的完整计划仍是提案/测试输入。转个人使用前必须重新确定个人基线和实际确认，
不把开发导入/启用记录自动当作个人批准。

## 4. 受支持升级与移除审核

版本支持按开发计划第 13 节执行：窗口内正常自动转换；过窗开发根提示重装并新建目录，
旧目录保留。R2已于2026-09-21实现schema14下界写前拒绝，开发验证27/27通过；
新候选的源码回归与本机检查仍须单独记录，不能继承旧包结果。新目录从内置 catalog 获取
完整最新动作库，不依赖旧根手动导入。旧审核不自动认证新图片。

动作库的移除与恢复审核需选择准确目标，冻结内容/原因/影响并显式提交。申请不改变可用性。
决定记录真实来源、实际时间与原文；快捷填入不产生默认事实。内容变化须新申请，引用影响
变化须刷新再确认。批量应用失败全部回滚，输入保留。发行方撤回不能靠本地恢复覆盖。

批准移除后阻止未来选用/新开始；暂停训练和历史依赖冻结内容，不连带删除变式、审核或导出。
恢复检查当前内容/图片，仍需单独启用并重新确认受影响计划；不复活旧审批或旧设置。
技术检查使用合成根，真实决定与真实内容审核分别记录。

## 5. 个人数据阶段的启动条件

等待用户明确“可以转入个人数据”的决定，再记录：应用/源码与二进制身份、catalog/schema、
个人根、准备转入的具体内容、被排除的合成记录及完整计划确认。不得自动搬迁整个开发根。
新根读取最新内置库；需要成为个人数据的内容按当时确认的范围迁入，具体机制届时确定。

满足当前图片/启用规则、完整计划已确认、适用本机检查通过后，才进入 W4。
W4与外部复核不阻塞本地发布。独立Windows验收仅在明确公开release时成为门槛；
用户开始真实观察不代表该项通过，也不自动启用公开发布任务。

## 6. W4 真实观察与修订模板

复制空表至个人根 `reviews/w4-observation-<日期>.md`，由用户填写真实事实。
个人原件/截图/导出保留在个人根，仓库只保留空模板及非个人结论。未知保持未知。

即使导出单次会话也可能带此前上下文；在观察表标明排除 ID，不能篡改原始导出。

### 6.3 专家修订与历史核对

1. 导出目标个人根真实证据，列明计入/排除 ID、反馈及当前 v2 回复 schema。
2. 保存真实答复原件/来源/发生时间，要求依据具体会话/反馈说明调整理由；未知不补造。
3. 导入完整 v2 草稿，核对完整处方、差异、精确指导/图片与原始依据，再明确激活。
4. 导出并按相同 session ID 核对冻结计划、逐轮成员/侧别、实际组、原文、事件、审核及撤回。
   正常新增反馈/留痕备注修正单独解释；不要求不同时间的整个导出文件哈希相同。
