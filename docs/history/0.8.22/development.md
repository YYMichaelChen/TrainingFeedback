## 实现及身份

- `data/database.py`：提交本身失败也进入回滚；回滚失败时关闭连接并继续抛出原始
  事务异常，以回滚异常为原因并明确连接不可复用。事务体异常沿用同一收敛路径。
- `application/library_service.py`、`library_workflow.py`：快照资源、审核附件和新示意图
  的失败清理不再覆盖原始用户动作异常；不能立即清理的快照仍由下次根打开恢复。
- `error_messages.py`、`main.py`、`ui/main_window.py`：每次显示异常都更新最近诊断，
  记录本地时间、操作、应用版本和最多 8 层异常链；总长最多 4096 字符，不序列化完整
  计划、训练备注、审核原件或堆栈。启动组装异常关闭已打开上下文并退出，页面创建失败
  记录对应页面；诊断生成失败不替换原异常。
- `ui/release_updates.py`、`group_plan_page.py`：安装包校验完成后先处理可见编辑／确认
  窗口。计划编辑继续提供保存草稿、放弃修改、继续编辑；只有保存或放弃实际关闭后才
  冻结主窗口并启动外部启动器。继续编辑、保存失败或未处理窗口都保留已校验 Setup，
  不启动退出计时，可稍后继续安装；启动器准备失败才恢复编辑。
- `application/release_updates.py`、`update_launcher.py`：更新目录带版本化任务租约，
  记录进程 ID 与 Windows 创建时间；外部启动器在报告 ready 前登记自身，并在等待
  Setup 结束期间保持活跃所有者。启动清理只删除格式严格匹配且所有精确所有者都已
  退出的目录；活跃、无权限确认、格式损坏或不可读租约原样保留。
- 应用 `0.8.22`；schema `26`、内部编辑格式 `2`、plan/evidence contract `5`、
  catalog `070-illustrated-3` 均不变。schema26 的应用范围扩展为 0.8.21–0.8.22；
  SQL、迁移入口、外部 wire schema、内置动作／指导／图片及历史冻结事实未改变。
