## 修复范围

原安装器配置 `UsePreviousAppDir=yes`，允许 Inno 在启动时继承旧安装目录；
该行为见 [官方说明](https://jrsoftware.org/ishelp/topic_setup_usepreviousappdir.htm)。
此外，原搬迁检查把缺失旧目录仍当成待卸载的安装，导致缺归属文件报错。
原 MD 只启动安装包、不传本次程序目录，并复用 `$program` 等旧验收变量，
不能把本次路径和旧测试上下文可靠分开。这些均由我们负责修正。

- 关闭未经本应用校验的 Inno 历史目录继承；正常默认是 Windows 当前用户的
  `%LocalAppData%\Programs\TrainingFeedback`。只有程序目录、归属、payload
  和卸载器校验通过的现有安装才能被预填，保留有效当前安装的重装/搬迁流程。
- helper 先验证旧路径及数据边界；旧程序目录已不存在时清除本次进程里的旧
  路径，不再触发搬迁。目录仍存在但归属未知时继续拒绝，不自动删除或补造记录。
- 注册表读取失败时明确把变量置空；日志分别记录登记旧目录、默认目录、
  所选目录和准备搬迁来源，后续错误可精确定位。
- 中文手动清单改用专用 `tf080` 变量、新的测试父目录，并在启动时显式传
  `/DIR`。准备命令包在同一脚本块里；准备失败后不会继续初始化并误用旧变量。

变动只有安装器编排和文档，不改应用、schema、catalog、wire 或数据处理。
同一release-0.8.0 minor scope 的既有26个安装helper用例通过（0.39s），累计
仍100/100；这些不证明 Inno UI 的实际默认和搬迁行为。新包从干净源码重建并
静态核对，候选身份另记。没有自动运行安装器或客户端；开发者实际复验仍未运行。
